## The product question

When a patient-support case stalls, finding a plausible answer is only part of the work. Which document is missing? Does the guidance apply to this case? What can the reviewer actually do next?

Pathway is an independent AI case-resolution prototype for non-clinical pharmaceutical access work. My role combines product framing and hands-on prototyping. It explores assistance for office access coordinators, field reimbursement managers, and patient-support case managers, using fictional cases and reference documents throughout.

## The experience

The case snapshot stays beside the conversation. A person can ask what is missing, follow up on why it matters, or prepare an office email and case briefing without losing the recorded context. On mobile, a context drawer keeps the conversation readable.

Each answer carries inspectable source passages and retrieval details. Activity shows knowledge search, answer preparation, and reference checks. Drafts remain available for human review; the application does not send them. Saved answers retain their original case and sources when the user changes Knowledge Packs or reloads within the browser session.

Recent conversation resolves references such as “Why?” It does not create new facts about the case. Superseded and unrelated documents are visible in the knowledge browser but are excluded from new answers. A bounded format repair reuses the same evidence rather than opening an unrestricted retry loop.

## Decisions and design lessons

**Case state and conversation need different rules.** A convincing sentence in chat is not evidence that a document arrived or a case progressed. Keeping the recorded snapshot separate protects that distinction.

**A valid citation is not the same as a supported claim.** Checking that a cited ID was retrieved catches one failure mode. Reviewing whether the passage supports the actual wording remains a separate evaluation problem.

**Visible progress should help inspection.** Search and validation activity make waiting more understandable, but also leave a useful record after an answer completes. The activity comes from application events rather than additional model calls.

## Current state and next step

The public demo supports questions, follow-ups, source inspection, and reviewable drafts across three synthetic scenarios. The repository documents automated checks and a synthetic conversation evaluation, including partial results and limitations. Those findings do not establish clinical validity or real-world effectiveness.

The next useful evaluation targets answers that cite the right source but overstate what it establishes. [Source and evaluation notes](https://github.com/ktakeuchi21/case-resolution-agent) provide the implementation detail behind this case study.
